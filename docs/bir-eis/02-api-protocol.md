# EIS e-invoice API protocol

Source: _EIS e-invoice API development guide_ (`source/EIS e-invoice API development guide.pdf`, chapters
3, 6 and 7), the sample code in `source/sample-code/`, and `source/API Error Solution Table v1.1.xlsx`.
Implemented in `src/server/eis/crypto.ts` and `src/server/eis/BirEisGateway.ts`.

## Endpoints

| API                     | Method and path                                           | Purpose                                                                |
| ----------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------- |
| Authentication          | `POST /api/authentication`                                | Get an auth token and session key (valid 6 hours)                      |
| Invoice Issuance        | `POST /api/invoices`                                      | Send 1–100 e-invoices under one `submitId`; returns an acknowledgment  |
| Inquiry Result          | `GET /api/invoice_result/{submitId}`                      | Processing status and per-e-invoice result                             |
| Invoice Result Callback | `PUT {taxpayer URL}/api/{version}/receive_invoice_result` | Optional: BIR pushes the result (built by the taxpayer; not used here) |

Sandbox base URL: `https://eis-cert.bir.gov.ph`. The production URL is e-mailed after the PTT. The guide
also shows `/api/{version}/invoice_result/...` and `https://eis-api.bir.gov.ph/v2/...` as examples; the
sample code uses the paths above. The HMAC is computed over the path actually requested, so a production
URL with a path prefix works as long as BIR expects the full path. **Confirm the production paths with the
URL BIR sends.**

## Headers (every call)

| Header            | Value                                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `accreditationId` | EIS Cert Number (8 digits; first 2 = system type: 10 web portal, 20 CAS, 31 POS, 32 CRM, 51 ASP-CAS, 52 ASP-POS) |
| `applicationId`   | Application ID from the portal                                                                                   |
| `datetime`        | Philippine time `yyyyMMddHHmmss`; must be within 10 minutes of the EIS clock (E05)                               |
| `authorization`   | `Bearer ` + base64(HMAC-SHA256(key, datetime + METHOD + path without domain))                                    |
| `authToken`       | Issuance and Inquiry only: the token from Authentication                                                         |

HMAC key: the **Application Key** for Authentication (and for BIR's callback to us); the **session key** for
every other call.

## Cryptography

| Use                            | Algorithm                                                                                                                                        |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Authentication request `data`  | RSA PKCS#1 v1.5 with the EIS public key over `{"userId","password","authKey"}`; base64                                                           |
| `authKey`                      | 32-character random string generated by us for this call                                                                                         |
| Authentication response `data` | AES-256-CBC, key = `authKey` bytes, IV = first 16 characters, PKCS#7; base64                                                                     |
| Issuance request `data`        | Each e-invoice JSON signed as a compact **JWS RS256** (`{"alg":"RS256","kid":<key ID>}`), joined with `,`, then AES-256-CBC with the session key |
| Issuance response `data`       | AES-256-CBC with the session key → `{accreditationId,userId,refSubmitId,ackId,responseDtm,description}`                                          |
| Inquiry response `data`        | JSON (shown unencrypted in the guide; the app also accepts an encrypted string)                                                                  |

`submitId` = `{EIS Cert Number}-{yyyyMMdd}-{12 random hex}`, unique per call (E14 on reuse).

## Processing results (Inquiry Result / Callback)

`processStatusCode`: **01** completed (per-e-invoice results in `processedDocuments`), **02** in progress,
**03** unable to process (`failReasonStatusCode` FRS001 unknown submitId, FRS002 decryption failure).

| Result code | Meaning                                                                                      | App status                            |
| ----------- | -------------------------------------------------------------------------------------------- | ------------------------------------- |
| SUC001      | Passed all verification; registered                                                          | accepted                              |
| SYN002      | Invalid digital signature                                                                    | rejected                              |
| SYN003      | `EisUniqueId` already registered                                                             | accepted (earlier send registered it) |
| SYN004      | Schema error (missing/duplicate fields, codes, types, number formats)                        | rejected                              |
| ERR001      | Seller TIN not registered with BIR                                                           | rejected                              |
| ERR002      | Issue date invalid, after the transmission date, or different from the date in `EisUniqueId` | rejected                              |
| ERR003      | Transmission date invalid                                                                    | rejected                              |
| ERR004      | Sales and VAT amounts with different signs, or VAT ≠ 0 on zero-rated/exempt                  | rejected                              |
| ERR005      | Invalid classification code                                                                  | rejected                              |
| ERR006      | EIS Cert Number in `EisUniqueId` differs from the transmitting system's                      | rejected                              |
| ERR007      | `PrevUniqueId` unknown or not the seller's, or present on a regular invoice                  | rejected                              |
| ERR011–015  | Document type, seller type, RBE local sales, transaction classification, RBE errors          | rejected                              |
| ERR999      | Other error                                                                                  | rejected                              |

(The code/description columns of this table are misaligned in the PDF text; the order above follows the
code and definition lists.)

## API errors (`errorDetails.errorCode`)

| Code    | Meaning                                         | App behaviour                                            |
| ------- | ----------------------------------------------- | -------------------------------------------------------- |
| E01     | Unknown accreditation ID                        | Connection problem: stop, keep queued, attempts not used |
| E02     | Unknown application ID                          | Same                                                     |
| E03     | Expired/invalid token                           | Re-authenticate once and retry                           |
| E04     | HMAC mismatch                                   | Connection problem                                       |
| E05     | `datetime` off by more than ~10–15 min          | Retry (check the server clock)                           |
| E07     | IP not whitelisted (production)                 | Connection problem                                       |
| E08     | Test number locked (certificate requested)      | Connection problem: switch to the real EIS Cert Number   |
| E14     | Duplicate submitId                              | Retry with a new submitId                                |
| E19     | Sandbox: more than one call per 10 s            | One batch per run in the sandbox                         |
| E21–E24 | Decryption, JSON, user/password, authKey format | E23/E24 connection problem; others retry                 |
| E99     | EIS internal error                              | Retry                                                    |
